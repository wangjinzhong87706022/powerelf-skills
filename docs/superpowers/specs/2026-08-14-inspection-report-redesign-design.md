## 1. 背景与实证（为什么改）

### 1.1 实跑发现：报告"太简单"的机制

用户在 Hermes 实问"对全部设备执行一次完整智能巡检：覆盖近 7 天所有监测维度"
（79 秒，agent 全程仅 1 次工具调用）：

- 图表 PNG 确实重新生成（`reports/` 18:02 时间戳），但没进任何交付物。

### 1.2 数据核对：9 条 finding 中 6 条精确命中，3 个真实缺陷

| Finding | 核对结果 |
|---|---|
| GNSS 97：1.200mm/d、12.00mm | ✅ 精确命中 |
| 雨量 85：35.0mm @ 08-13 23:00 | ✅ 精确命中 |
| 闸门 90：1.18→2.50m | ✅ 值存在（同一时刻两条记录） |
| 泵站 89：50/62/38A → 24.0% | ✅ 精确命中 |

三个缺陷（详见 §5 修复方案）：

1. **"当前值"失实**：471.89 是窗口中部尖峰（仅 5 行 >460kPa），最新值已回落 455.12，
   报告却写"当前 471.89kPa"——违反 SKILL.md 既有纪律"当前值与窗口峰值双值"；
2. **根因证据跨站重复累计**："-2h 累计降雨 240mm" = 60mm/h × 2 行/小时 × 2h。
   `st_pptn_r` 近 3 天 126 行 `st_id` 为 NULL（2 行/小时），诊断路由 R1② 的窗口 SUM
   无站归属去重——去重口径实为约 120mm；
3. **spike 降级失灵**：尖峰已回落仍报 WARNING + root_cause；按纪律 #7 应降 INFO
   且不进诊断路由。

### 1.3 数据可行性硬约束（已验证）

- `eq_equip_base.status` 仅 0/1/2 三枚举（离线 54 / 在线 72 / 异常 2，deleted=0 口径）——
  用户模板中的"休眠"状态不存在，只能三分类；
- `ew_info_message` 时间列是 `gather_time`（非 `tm`），告警趋势/等级统计数据可用；
- `wq_pcp_d` 时间列为 `create_time`（维度有数据，通用 `tm` 探针不适用）；
- `eq_equip_base` 无经纬度列（GIS 图数据源待 P1 验证站点基础表）。

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 交付形态 | 聊天摘要 + 完整 .md 报告文件**双交付**（Word/PDF 导出器留待后续） |
| 风险口径 | **三档中文标签**：CRITICAL→重大 / WARNING→重要 / INFO→提示；"一般"档恒 0 并注明（四色规范中黄色档保留给未来四档扩展） |
| 本期范围 | P0 + 数据修复；P1（GIS/热力图/MAD TOP10 图/告警等级图）下期 |

| 图色规范 | 水利部水情预警四色体系：红 I `#E53E3E` / 橙 II `#ED8936` / 黄 III `#ECC94B`（保留档）/ 蓝 IV `#3182CE`；正常绿 `#38A169`；告警图按 `level_r` 直接套红橙黄蓝 |
| 时间范围 | **全链路参数化**：巡检窗口 N 从用户问题解析（"近 X 天/昨日/本周/本月"→ `--days N`，未指明默认 7），报告章节、统计、图表、文件名全部随 N 生成，**任何位置不得硬编码 7** |

（报告必须且只能由 inspection_analyzer.py 一次产出），两次查询窗口不一致正是历史上
"524 记录 vs 54/128"口径事故的成因。

## 3. 报告模板（8 章节）

模板文件：`references/report-template.md` 重写。占位符由 `render_report.py` 填充。

```markdown
# 水利设备智能巡检报告
## 一、报告基础信息
  报告名称 / 巡检时段（起止日期精确到小时）/ run_id
  巡检范围：全部监测设备 N 台（在线 a · 离线 b · 异常 c）
  覆盖维度：15 维（有数据 x / 无数据 y，覆盖清单见附录）
  执行方式：自动化智能巡检 + 5 层判定体系（阈值→变化率→趋势→MAD→关联）

## 二、总体概况（领导 30 秒版）
  风险分级：重大 n1 · 重要 n2 · 提示 n3（"一般"档本系统暂无对应级别，恒为 0 并注明）
  整体结论：一句话（存在突出风险 / 总体平稳 + 核心问题）

## 三、异常清单（逐条三问，按风险降序）
  ### F005 ｜位移监测｜GNSS 测点 97 ｜ ⏰ 发生时间 ｜ 已回落/仍高位
  > 严重程度：🔴 重大
  > 初步根因：设备类/工况类（启发式标签，按维度映射：设备状态/离线维度→设备类，
              其余→工况类；报告中注明启发式）+ 诊断证据链
  > 下一步行动：处置动作 + 时限
  每条附：变化简述（峰峰值双值）→ 链接对应时序图

## 四、分维度统计分析
  4.1 设备状态统计（三分类：正常/离线/异常，注明"休眠"枚举不存在）
  4.2 巡检周期告警统计（等级×频次 + 按时趋势，ew_info_message.gather_time，窗口=N 天）
  4.3 MAD 异常统计（离群测点清单：z 值/离群时间/是否回落）
  4.4 多指标关联分析（水位-渗压等联动结论）
  4.5 专项监测小结（水情/渗流/GNSS/闸泵/水质/白蚁/墒情各 1-2 行，正常维度也写）

## 五、正常测点汇总（精简）
  按维度：N 维无异常，覆盖测点约 X 台/点；无异常设备 N 台

## 六、综合风险研判
  短期 / 长期，全部从 findings 事实规则拼装，遵守统计措辞护栏，不做自由推断

## 七、任务跟踪与闭环
  紧急处置（重大项）/ 计划检修（设备类重要项）/ 持续观测（工况类重要项）
  复查要求：重大 24h、重要 72h（固定模板）+ 资源协调建议

## 八、附件
  图表索引（PNG 列表）/ 原始告警统计表（等级×日交叉表）/ 覆盖清单（T8 已有）
```

制图统一约定（全图适用）：

- 标题格式【图表名称｜统计时段：YYYY-MM-DD ~ YYYY-MM-DD】；
- 坐标轴带水利标准单位（m / kPa / mm/d / L/s / mm/h 等）；
- 无 3D、无渐变；黑白打印可辨（色板 + 实/虚/点划线型双编码）；
- 时序图默认小时级粒度；**统计图聚合粒度随窗口 N 自适应**：N≤2 天按小时、3~31 天按日、>31 天按周；
- 所有图表与统计的窗口一律取自 `--days N`，标题中的统计时段由 N 计算起止日期；
- 图色按 §2 水利四色规范；趋势/关联过程线沿用蓝色系水位、红色系渗压的水文惯例。

T8 已有 4 类图（趋势×4 / 异常分布+severity 饼 / 离线双口径 / 水位-渗压双轴）全部保留，
severity 饼图配色同步换成水利四色。

## 5. 数据修复（3 项，analyzer 内）

### 修复 1：降雨根因证据跨站重复累计

- 位置：诊断路由 R1② `_diagnose_pressure_outlier` 降雨查询；
- 改法：逐时刻去重口径 `SELECT SUM(mx) FROM (SELECT MAX(p) AS mx FROM st_pptn_r WHERE … GROUP BY tm) t`
  再进 ≥10mm 判据（去重后约 120mm，仍命中"降雨入渗"，结论不变、量级归正）；
- 证据文本强制注明口径："面雨量约 X mm（窗口内 Y 行未归属站点，按逐时去重）"；
- `st_id` NULL 行作为数据质量提示进入报告 Data Notes。

### 修复 2：突变类 finding 强制双值口径

- 突变/MAD finding 的 detail 强制携带：峰值+峰值时间 ｜ 当前值+回落标志；
- 回落判定：`peak_tm < latest_tm` 且 `|latest − median| < 3.5×MAD`（与 MAD 层 z=3~4 同口径的量化判定带）→ "已回落"；
- 聊天摘要、异常清单、图表阴影区间三处同步显示回落标志。

### 修复 3：spike 模式降级接入

- 突变/MAD 判定输出复用既有 `pattern` 三分通道（spike/step/drift）；
- 尖峰已回落 → `spike` → 降 INFO（提示档）、不进自动诊断路由；`step`/`drift` 维持原级；
- 已知影响：本次 F004（z=56.8，已回落）将从"重要"降为"提示"——符合预期（已回落的
  极端离群更像毛刺），必须全量评测验证不踩已知口径冲突。

## 6. 聊天层双交付路由（SKILL.md 改造）

- 工具命令区首条改为：完整巡检请求 →
  `python3 impl/inspection_analyzer.py --db "$DB_URL" --days <N> --output reports/insp-<YYYYMMDD>-<N>d.md`
  一步出报告（8 章节 + PNG 嵌入落盘）；
- **时间范围解析规则**（SKILL.md 明示，agent 解析后传参）：用户问题中的时间表达 →
  `--days N`（"近 X 天"→X；"昨日/昨天"→1；"本周"→距周一天数；"本月"→当月累计天数；
  "近一周"→7；未指明→默认 7）；analyzer 不做中文解析，只收数值参数——解析职责在 agent 层；
- `--output` 给定时 stdout 附带简短摘要块（状态行 + 报告路径 + 重大项清单），
  agent 拿来即用；聊天回复 = 摘要 + 文件路径；
- `--json` envelope 契约**不动**（评测/程序消费场景继续用）；
- envelope 字段零删减、退出码语义不变（0/2/3/4/5）。

## 8. 测试与验收（4 道闸）

1. **单测**：`render_report` 纯函数——给定 context dict 断言 8 章节齐全、三问结构、
   风险降序、回落标志、启发式标签；
2. **真实库冒烟（铁律）**：对 `powerelf_srm_yml` 跑 `--days 7 --output`，断言
   summary 计数 ≡ findings 明细、图表 PNG 落盘、报告含全部章节；
   **另跑 `--days 1` 与 `--days 30` 各一次**：断言报告标题时段、统计窗口、
   图表标题与聚合粒度随 N 正确变化（防 7 硬编码回归）；
3. **评测不退化**：47 巡检用例 + EVAL10 全量重跑，综合分 ≥ 基线 0.755；
   因 3 项修复引起的用例翻转逐条人工审（防 teaching-to-the-test 反向问题）；
4. **契约不变**：envelope 字段零删减、退出码 0/2/3/4/5 语义不变。
