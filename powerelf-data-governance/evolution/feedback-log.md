# 数据治理执行反馈日志

## 使用说明

当用户反馈判断不准确（漏报/误报/参数不合适）时，在此记录事件、原因分析和改进措施。
分析反馈模式后，更新 `parameters.md` 中的参数值。

## 日志格式

```
## YYYY-MM-DD 事件标题
- **事件**: 描述发生了什么
- **原因**: 分析为什么会出现这个问题
- **改进**: 采取了什么措施
- **状态**: 待调整 / 已调整 / 已验证
- **相关参数**: parameters.md 中的参数名
```

## 日志条目

## 2026-08-20 插值/缺失检测不覆盖时间断档（评测发现，人工采纳）
- **事件**: hermes-eval-20260819-183116 routing-evals-v1/4 答题中发现：`interpolate.py` 与 `missing_detector.py` 只检查已存数据的 NULL 值/时间戳连续性，**不检测时间断档**（设备停报造成的整段空窗）。st_rsvr_r 实测：7 天窗口全设备零缺失，但 30 天窗口 eq_id=NULL 源存在 244h 断档（08-06→08-16）。
- **原因**: 两个脚本的缺失判定以"行内字段为空"为口径，停报期间根本没有入库行，行级检测天然漏检。
- **改进**: SKILL.md「插值/缺失补全」行补充已知限制与工作法（先按 eq_id 分组检测时间断档——间隔>2h，再判断是否插值）；脚本层断档检测参数化属后续人工开发。
- **状态**: 已调整（文档）；脚本修复待排期
- **相关参数**: 无（无现成参数，属能力缺口）
- **出处**: 评测 agent 发现并就地写入被测 SKILL.md（触发代码冻结违规，已回滚后人工采纳）；取证见 `docs/eval-mutation-forensics-20260820.md`
