# 最佳实践

> 高频错误、QA 闸、边界规则汇总。

---

## Pitfalls（高频错误）

**来自 2026-07-17 实测总结**

1. **MAD 窗口参数误设**
   - 窗口过小漏检，过大约束无意义
   - 建议：从默认值开始，根据数据特性调整

2. **插值长度误用**
   - 连续缺失超过 3 天不应插值
   - 插值结果不可靠，需现场复测

3. **评分分母选错**
   - 应在线设备数 ≠ 有数据设备数
   - 需从 eq_equip_base 统计，不是从监测表

4. **离线阈值错配**
   - 不同站型离线阈值不同（水位站 360 分钟，其他 60 分钟）
   - 来源：`dg_equip_offline` 或 `eq_business_equip_relation.offline_threshold`

5. **回写权限失控**
   - 只读账号不应执行 writeback
   - 执行前检查权限

## Validation Gate（交付前 QA 闸）

报告交付前必须检查以下事项：

### 1. 数据完整性
- [ ] 时间窗口内的数据是否完整？
- [ ] 缺失率是否在可接受范围内？

### 2. 异常判定合理性
- [ ] 异常值是否经过 MAD/IQR 验证？
- [ ] 是否排除了极端事件（汛期高水位）？

### 3. 设备状态一致性
- [ ] 离线设备是否与 eq_equip_base.status 一致？
- [ ] 业务映射是否完整？

### 4. 置信度评级

| 置信度 | 条件 |
|--------|------|
| **高** | 数据完整 + 异常明确 + 设备状态一致 |
| **中** | 数据基本完整 + 异常基本明确 |
| **低** | 数据缺失较多 + 异常判定存疑 |

## 边界规则

以下情况**必须人工确认**，Agent 只能建议不能决策：

| 场景 | 原因 |
|------|------|
| 数据插值超过连续 3 天 | 插值结果不可靠，需现场复测 |
| 设备离线超过 7 天 | 可能是设备故障而非通信问题 |
| 多台设备同时异常 | 可能是系统性问题而非个别设备 |
| 异常值在设计允许范围内 | 可能是正常工况，需专家判断 |
| 厂商排名用于采购决策 | 需结合价格、售后等多维度评估 |

**反例（不要做的事）**：
- ❌ 不要自动插值后直接覆盖原始数据
- ❌ 不要在没有确认的情况下将"异常"改为"正常"
- ❌ 不要跳过缺失检测直接做质量评分
- ❌ 不要对单条数据做全局性结论
